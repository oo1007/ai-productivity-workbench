# AI 简报与个人效率工作台
### AI Productivity Workbench

把资讯整理和日常行动放进一个工作台：通过 Codex 工作流组织中文简报，并探索“自然语言输入—人工核对—日历同步”的效率工具交互。

**个人项目 · AI 工作流 · 信息整理 · 个人效率工具**

[打开工作台](https://oo1007.github.io/ai-productivity-workbench/) · [查看简报样例](https://oo1007.github.io/ai-productivity-workbench/brief.html) · [返回作品集](https://github.com/oo1007)

## 项目解决什么问题

资讯分散在不同来源，日常任务又需要转换成具体安排。这个项目把两类操作放在一起：一侧帮助整理需要关注的信息，另一侧帮助把一句行动描述转换成可核对的日程草稿。

## 两部分能力

| 部分 | 当前内容 | 使用边界 |
|---|---|---|
| 简报工作流 | 公开 RSS / Atom 来源采集、时间筛选、标题去重、Markdown / JSON 输出、中文简报与归档页面 | 简报页面是已发布的历史内容，不承诺实时更新 |
| 行动工作台 | 自然语言日期与时段解析、分类、草稿保存、同步确认、连接状态与日程展示界面 | 日期解析由前端规则实现；日历读取和写入依赖本地同步服务 |
| 语音输入 | 浏览器支持时，将语音转为输入文本 | 取决于浏览器能力与用户授权 |

## 建议这样体验

1. 打开工作台，在输入框描述一件行动，例如“明天下午 3 点到 4 点学习”。
2. 点击解析，检查识别出的事项、日期、时间和分类，并尝试手动修改。
3. 查看连接状态，理解“草稿”和“已同步日程”的区别。
4. 进入每日简报，查看资讯如何分类、引用来源并按日期归档。

**外部访客未启动本地同步服务时，可以查看页面与解析交互，但无法直接同步到作者的日历。** 当前仓库没有包含该同步服务的完整后端。

## 设计思考

**先核对，再执行。** 日期和时间可能存在歧义，解析结果应允许用户修改，并由用户明确触发同步。

**长期入口与每日内容分开。** 工作台作为固定入口，简报通过独立页面更新，避免每天生成内容时覆盖工具界面。

**展示失败状态。** 本地服务、连接或授权不可用时，需要说明原因，让用户知道草稿是否保留、是否已经执行。

## 运行方式

前端可用静态网站服务器打开，例如：

```bash
python -m http.server 8000
```

资讯采集脚本可单独运行：

```bash
python skill/world-hot/scripts/collect_world_hot.py --hours 24 --format markdown --output world-hot-today.md
```

工作流说明见 [World Hot Skill](skill/world-hot/SKILL.md)。当前页面里的日历能力会请求本机同步服务；仅启动静态服务器不会自动启用日历同步。
